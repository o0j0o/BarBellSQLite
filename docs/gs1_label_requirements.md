## The six required fields (pallet + carton labels)

Both the pallet label and the secondary-packaging (carton/box) label carry the same six
data elements, each with a GS1-128 Application Identifier:

| AI | Field | Source | Status in BarBell |
|---|---|---|---|
| (00) | SSCC (18-digit Serial Shipping Container Code) | **CLC generates it** - never sourced from Label Traxx | `src/sscc.py::SSCCGenerator` (confirmed against CLC's real GS1 Company Prefix) |
| (02) | GTIN of the trade unit (GTIN-14) | **JWN provides it per SKU** - CLC must not create/register GTINs | **NOT FOUND in Label Traxx** - see "GTIN: the missing piece" below |
| (37) | Quantity (trade units on the pallet/carton) | Label Traxx | `TicketItem.OrderQuantity` (confirmed) |
| (10) | Batch / Lot code | Computed | `Ticket.Number` + `Product.ProdNum` ("ProductNo"/"P/N"), no separator - **matches JWN's own decision**: "proceed using Job # + P/N as the batch number" (Ameika Turner, JWN). Corrected 2026-09-09: originally implemented with the item number (`Product.Name4`) instead of `ProdNum` - the user clarified "P/N" means `ProdNum`. `build_batch_number()` in `src/batch.py` unchanged; the fix was in which field `src/labels.py` passes to it. |
| (11) | Production date (YYMMDD) | Label Traxx | `Ticket.PressStat` (decided "for now", low confidence - see QUESTIONS.md) |
| (15) | Best Before Date (if applicable) | Unconfirmed | Not yet checked - rum may not need one; confirm with JWN/product master whether this applies |

Free-format section (plain text, not barcoded): Company name, production plant, item
number, item description, Best Before Date if applicable - all straightforward from
`Ticket`/`Product` except Best Before Date (see above).

## GTIN: the missing piece

Per the briefing: **JWN owns and provides the GTIN. CLC must never create or register
one.** The wiki doc's JWN review confirms this in practice - Ameika Turner gave CLC an
exact GTIN value (`0072105000635`) to encode for one specific SKU, and separately asked
CLC to "supply a list of all JWN item codes CLC provides and their corresponding GTINs
- with LCJ's listed separately."

**I checked whether this Product record already has a GTIN in Label Traxx and it does
not appear to.** `Product.BC_Symbol` = `'UPC'` and `Product.BC_HRStart` =
`'7 21059 00063 5'` look at first glance like they might be it, but decoded
(`721059000635`, a 12-digit UPC-A) they don't match Ameika's GTIN once both are
normalized to GTIN-14 (`00721059000635` vs `00072105000635` - different numbers). These
`BC_*` fields are most likely CLC's own barcode setup for the *product* label artwork,
not the *logistics* GTIN JWN assigns - a different thing per the briefing's own
GTIN-vs-SSCC distinction.

**Decided (2026-09-09): GTIN goes into Label Traxx.** Someone else enters it there through
Label Traxx's own UI (not BarBell - `ReadOnlyConnection` only ever reads); BarBell reads it
back out like every other field.

**Still needed before this can be implemented: which column?** All of Product's
`Name1`/`Name2`/`Name3` are blank on the sample record (only `Name4` is populated, with
the item number) - so a GTIN hasn't been entered for any product yet, and there's nothing
to inspect empirically. Once CLC starts entering GTINs in Label Traxx (as part of
compiling the item-code<->GTIN master list), re-run `probe_odbc.py` against a
product that actually has one populated to confirm which column it landed in - don't
guess it's `Name1`/2/3 just because they're the other empty slots.

## SSCC: the missing piece

**SSCC is not a Label Traxx field at all - it's generated by CLC, one unique number per
pallet, and a number can never be reused once issued (hard GS1 requirement).** The
briefing frames this as the single biggest risk area, because CLC runs three plants
(Barbados HQ, Label Crafts Jamaica, CLC Dominicana) that could otherwise collide on the
same number, and recommends a **central automated SSCC generator** (their "Option
3"/"Option B") over per-plant number ranges or a spreadsheet.

**Decided (2026-09-09): just this plant for now.** BarBell generates SSCCs for this plant
only (not the central multi-plant authority the briefing's "Option B" describes) -
smaller to build now; cross-plant collision risk is managed some other way, outside
BarBell's scope for the moment.

**Built (2026-09-09).** CLC's real GS1 Company Prefix (`08600157112`, from the GS1
Company Prefix Certificate - Account 30391419, Caribbean Label Crafts Ltd, issued
2026-04-07, renew by 2027-04-30) is now in `.env` as `GS1_COMPANY_PREFIX`, alongside
`SSCC_EXTENSION_DIGIT` (currently `0`) and `SSCC_STATE_FILE`.

`src/sscc.py` provides:
- `gs1_check_digit()` / `build_sscc()` - pure functions, check-digit math verified
  against two independent worked examples from GS1's own documentation, not just
  self-consistency (see `tests/test_sscc.py`).
- `SSCCGenerator` - persists the last-issued serial reference to a local JSON state
  file (`SSCC_STATE_FILE`) and refuses to start from zero implicitly: `initialize()`
  must be called once, explicitly, and refuses to run again on an existing file (to
  avoid ever reissuing a number after the state file is lost or copied to a new
  machine).

With an 11-digit company prefix, the serial reference field is 5 digits (16 - 11), so
one extension digit gives 100,000 SSCCs before needing a new extension digit (0-9
available) or a design change - plenty of headway for "just this plant for now."

**Known limitation, in scope for later**: the state file has no cross-process locking -
fine for a single BarBell process on one plant, but would need a real lock (or a
database) before this could run concurrently from multiple processes, let alone become
the multi-plant central authority described in the briefing.

## How this fits the user's proposed architecture

The user's plan - an intermediary program that pulls job/item/quantity/date from Label
Traxx via ODBC, merges in the fields Label Traxx doesn't have (GTIN, SSCC), and emits a
CSV that BarTender consumes to drive the Zebra printer - **matches the CLC briefing's own
recommended architecture** (Step 1 GTIN reference table, Step 2/3 central SSCC generator,
Step 4 BarTender + Zebra printing). Nothing about it conflicts with the spec; the two
open items above (GTIN source, SSCC generation/scope) are exactly the two things the
briefing itself flags as unresolved risk areas, not something specific to this plan.
